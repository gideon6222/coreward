# Coreward

> **MIGRATION IN PROGRESS (branch `vite-migration`).** This file describes the
> state this branch will have *once merged*. `main` is still the pre-Vite site
> and is still serving the live game. **Merging this branch and switching the
> Pages source are one operation** — see "Cutover" below. Doing either alone
> takes the live game down. `pre-vite` tags the last known-good pre-migration
> commit (`83a862a`).

3D planet-mining PWA. Dig toward a planet core, sell ore at the surface pad, buy
upgrades, break the core and the planet explodes, launch to a harder planet. Fuel
and heat are the two pressures pushing you back up.

Live: **https://gideon6222.github.io/coreward/**
Repo: github.com/gideon6222/coreward
Target device: Samsung S26 Ultra, Chrome, portrait, installed to the home screen.

## Stack

Vite build, deployed to GitHub Pages by GitHub Actions.

- three.js pinned to **exactly `0.166.0`**. Not a caret range: the lighting
  values below are calibrated to that version. It is bundled and tree-shaken
  rather than pulled from a CDN — 517 kB raw, 135 kB gzip, smaller than the CDN
  module it replaced, and it works offline.
- `base: './'` because Pages serves from `/coreward/`, not the domain root.
- The service worker is **generated by `vite-plugin-pwa`** from the real build
  output. It is not in the repo; do not hand-write one.
- Audio is 100% synthesised at runtime with Web Audio. No mp3, no wav.
- The icon is SVG. There are no binary assets in this repo, by design.

Phase 4 of the migration; `src/audio.js` is currently the only module boundary.

pre-Vite version and is not generated by the PWA plugin. The app already
installed on the phone is keyed to its `start_url` and `scope`, so regenerating
it risks the installed app rather than improving it.

## Deploy

Push to `main`. The workflow runs the golden tests and **only deploys if they
pass**. Pages serves the uploaded `dist/` artifact.

The Pages source must be set to **GitHub Actions**, not "Deploy from a branch".
In branch mode the raw source is served and the site is broken, because
`index.html` points at `/src/app.js` — an unbundled module importing a bare
`three` specifier.

**There is no cache constant to bump any more.** Workbox derives the precache
manifest from the real build output: the bundle's content hash is in its
filename, so a changed file is automatically a new precache entry. The old
hand-written `sw.js` needed `CACHE` incremented by hand on every single deploy
or installed PWAs kept serving the old build. That trap is gone. Do not
reintroduce it.

### Cutover (one time, not yet done)

`main` has no workflow and Pages is in branch mode, so two changes must happen
together:

1. Merge `vite-migration` into `main` (brings the Vite build *and* the workflow).
2. Immediately switch **Settings → Pages → Source** to **GitHub Actions**.
3. Watch the run finish, then hard-reload the live URL.
4. **Open the installed PWA on the phone.** Expect the *first* open to still
   show the old game: the old worker serves the old `index.html` from cache
   while the new worker installs behind it. **Close it fully and open it a
   second time** and you should get the new build. This handover was measured
   on a real old-to-new upgrade, not assumed - see below.

The upgrade path was tested end to end by installing the pre-Vite worker on a
clean origin, then serving the new build at that same origin:

| | Before | After reload 1 | After reload 2 |
|---|---|---|---|
| caches | `coreward-v5` (7) | workbox precache (5) | workbox precache (5) |
| `coreward-v5` | present | **deleted** | gone |
| loaded script | `app.js` | `app.js` (old, from cache) | `./assets/index-<hash>.js` |

`public/sw-legacy-cleanup.js` is what deletes the old cache. Workbox's
`cleanupOutdatedCaches` only removes precaches it created itself, so without
that script `coreward-v5` sat on the device permanently - measured at 1.31 MB
of orphaned data, including the old CDN copy of three.js.

The site is down between steps 1 and 2, so do them back to back. If it goes
wrong: `git revert` the merge and switch Pages back to branch mode, or reset to
the `pre-vite` tag.

## Tests

Golden safety net for the migration. **Zero dependencies** — it uses the built-in
node test runner, so it needs no install to run locally.

```
npm test
```

CI runs it on every push and pull request, and the deploy job depends on it.

`test/harness.mjs` does not import `src/app.js` — importing it would immediately
touch `document` and build a WebGLRenderer. Instead it reads the real source,
slices it at the `/* ============ three ============ */` banner, strips the
`import` lines and evaluates the pure prelude. **The tests run against shipping
code, not a copy of it.** If that banner is renamed, update `MARKER` in the
harness.

Baselines live in `test/baseline/*.json`. To re-record one deliberately, delete
the file and re-run.

Three things the harness handles that a naive snapshot gets wrong:

- **`Infinity` is encoded, not stringified.** Bedrock has `hard: Infinity`, and
  `JSON.stringify` turns that into `null`, so a round-tripped snapshot would
  silently lose it and still compare equal to itself. Non-finite numbers are
  written as `"__Infinity__"`, and bedrock is additionally asserted directly.
- **Line endings are normalised.** `core.autocrlf` is true on the dev machine, so
  a plain `git checkout` rewrites the baselines to CRLF while the harness writes
  LF. `.gitattributes` pins LF and the harness compares CRLF-agnostically, so it
  holds on a fresh clone and in CI.
- **Pathfinding has two tiers.** `findRoute()` is a BFS whose neighbour order is
  an array literal; when several shortest paths tie, that order alone picks the
  winner. The *contract* tests assert only what matters — connected, no solid
  rock, optimal length against an independent BFS using a different neighbour
  order. The exact path is pinned separately in `route-canary`. **If only the
  canary fails, the change is safe: re-record it.** If a contract test fails too,
  pathfinding is genuinely broken.

These cover pure functions only. Hit-stop, camera lerps and the autopilot spline
live in the frame loop and **cannot** be covered here. The side-by-side check on
the phone is the real test for those.

## Hard constraints

- **No binary files, ever.** The GitHub connector used to push here cannot commit
  binaries, so audio stays synthesised and images stay SVG. Treated as a feature:
  zero load cost, works offline.
- **The error overlay must be the first script in the document.** It sits in
  `<head>` in `index.html`, above everything else. On a phone with no devtools it
  is the only way to see a stack trace, and Vite hoists the bundled entry script
  into `<head>` at build time — a handler left down in `<body>` is registered too
  late to catch it. After any change to the head, verify by deliberately breaking
  an import, building, and confirming the overlay still displays the error.
- **AudioContext needs a real user gesture.** `audioInit()` is wired to the first
  `pointerdown`/`keydown`; Chrome blocks it otherwise.
- **three.js 0.166 is physically based.** Old tutorial light values render nearly
  black. Live values: ambient 1.6 in the open falling to ~0.2 deep, directional
  1.5 faded out below the surface, player point light 30 with decay 1.25.
- **Portrait aspect is ~0.46.** Only 6–7 of the 9 world columns fit horizontally.
  Camera distance is solved from a target row count (13) and panned within
  clamped limits; see `resize()` and the camera block in `frame()`.

## Feel rules that the game currently depends on

These are load-bearing, not decoration. Changing them changes how it plays.

- **Hit-stop.** `freeze` pauses the *simulation* for 35 ms on rock and 75 ms on
  ore. Camera and UI keep running off a separate raw delta (`raw` vs `dt` in
  `frame()`). Do not collapse those two deltas.
- **Three feedback channels per action:** particles in the block's own colour, a
  pitched sound, screen shake, plus a squash on the ship.
- **Pitch is randomised** on repeated sounds (playback rate 0.7–1.3) so drilling
  does not become irritating.
- **Autopilot flies a Catmull-Rom spline** over a breadth-first shortest route
  through dug tunnels, with ease-in-out. Stepping cell to cell reads as a
  fast-forward, which was rejected in playtest.
- **Fake bloom** is a 64px radial-gradient canvas texture on additive sprites.
  Pulse by animating sprite *scale*, not opacity, since the material is shared.
- **Sky is a CSS gradient** on `#game`, updated from game state ~8x/sec. The
  renderer runs with `alpha: true` and no scene background.

## Local development

Node is installed at `C:\Program Files\nodejs` and was added to the user PATH, so
a **new** terminal has `node` and `npm` on it.

```
npm install
npm run dev       # vite dev server, no service worker
npm run build     # production build into dist/
npm run preview   # serve dist/ exactly as Pages will
npm test          # golden tests
```

Service workers are disabled in `vite dev` on purpose — a cache-first worker on
localhost serves stale modules and wastes an afternoon. The in-app Claude browser
cannot register service workers at all, so any PWA check has to happen in real
Chrome or on the phone.
